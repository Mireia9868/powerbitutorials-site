# 10 — Dynamic Date Dimension

**Question:** A marked date table with fiscal-year support, and the time-intelligence measures that depend on it.

## Tables and columns assumed

- `Date` — generated by `DateTable.pq`
- `Sales` — `OrderDate`, `NetRevenue`

## Build steps

1. Create a blank query, paste `DateTable.pq`, name it `Date`. Set `StartDate`, `EndDate` and `FiscalStartMonth` at the top for your model.
2. Select the `Date` column → Column tools → **Mark as date table**. Skip this and every time-intelligence measure returns wrong numbers.
3. Set **Sort by column**: `Month` sorted by `MonthNo`, `YearMonth` sorted by `YearMonthNo`.
4. Relate `Date[Date]` one-to-many, single direction to `Sales[OrderDate]`.
5. Paste `Measures.dax` into a `Time Intelligence` folder.
6. Hide helper columns (`MonthNo`, `ISOWeek`, `YearMonthNo`) from report view.

## Self-check

`Date` must be contiguous with no gaps, start before the earliest fact date and end after the latest. With all filters cleared, `Revenue YTD` = `Revenue` (calendar year). `Revenue YoY %` is blank in the first year. `Share of Selected Total` reaches 100% at the grand total.

## Common traps — the three that produce wrong numbers silently

- **Fiscal YTD with plain `TOTALYTD`.** Without the `"6/30"` year-end argument, a July-start fiscal year is treated as calendar. Use `Revenue YTD (fiscal)`.
- **`PREVIOUSMONTH` on a partial month.** It returns the whole prior month, which overstates a comparison when the current month is in progress. `DATEADD` shifts the exact context.
- **`ALL()` where you meant `ALLSELECTED()`.** `ALL` ignores every slicer; `ALLSELECTED` keeps the user's selection. `Share of Selected Total` uses the latter on purpose.
- **Auto date/time.** Turn it off (Options → Data Load → Time intelligence) once a marked date table exists, or you get a duplicate hidden table and ambiguous relationships.
