# 02 — Market Basket Analysis

**Question:** Which products are bought together more often than chance would predict?

## Tables and columns assumed

- `SalesLines` — `OrderKey`, `Product` (one row per line item)
- `BasketPairs` and `BasketSingles` — generated by `MakePairs.pq`

## Build steps

1. Load `SalesLines` with `OrderKey` and `Product`.
2. Create a new blank query, paste `MakePairs.pq`, and name it `Baskets`. It returns a record with two tables; expand `BasketPairs` and `BasketSingles` into two separate queries (`= Baskets[BasketPairs]` and `= Baskets[BasketSingles]`).
3. Paste `Measures.dax` into a `Market Basket` folder.
4. Build a matrix with `ProductA` and `ProductB` on rows and `Pair Orders`, `Support (A,B)`, `Confidence (A->B)` and `Lift` as values.
5. Sort by `Pairs to Show` descending so only meaningful pairs surface.

## Self-check

`Support (A)` must be between 0 and 1. `Lift` = 1 means the pair is independent; above 1 means positive association. If `Lift` divides by zero, `BasketSingles` was not loaded — the `Support (B)` measure cannot find its denominator.

## Common traps

- Keeping self-pairs and both directions (A→B and B→A): they double-count and halve the lift. The `ProductA < ProductB` filter removes both.
- Not de-duplicating line items. One order with three of the same product becomes nine phantom pairs.
- Reading confidence as lift. Confidence can be high for a very common product even with no association; lift is the measure that strips out base popularity.
- Low counts. A pair bought twice has unreliable lift, hence the `>= 5` threshold in `Pairs to Show`.
